# 2026-10-15: S1, Knights Corner as a CPU of LLVM and clang

Everything was run on the rack and on card 0, with production idle.

## Patches

| Patch | What |
| --- | --- |
| 0011 | LLVM: `FeatureKNC` outside the SSE ladder; CPU `knc` (x87, cx8, fxsr, 64bit, knc) with x86-64's scheduling model and `generic`'s tuning; `+sse2` from the triple dropped for `knc` (subtarget and MC); `CK_KNC` in the target parser |
| 0012 | clang: no forced SSE2 for `knc`; `__MIC__ 1`, `__KNC__ 1`, `__knc`, `__knc__`, `__tune_knc__`; 64-byte cache line |

Sources for the facts: ISA reference 327364, appendix B (deleted
instructions); Intel C++ Compiler documentation, "Using Predefined
Preprocessor Symbols" (`__MIC__` and `__KNC__` are 1 for `-mmic`); SSDG
328207, the cache table (64-byte lines).

## What went wrong on the way

- **Tuning:** the first equivalence run had 271 of 1,485 objects differ, all
  `decl`/`incl` against `addl $-1` (slow-incdec tuning). `-march=x86-64`
  is tuned as `generic` (`X86TargetMachine::getSubtargetImpl`), not with
  `X86_64V1Tuning`. The `knc` CPU now takes `generic`'s list.
- **Stale patch export:** after `git reset --soft`, the new edit was
  unstaged, so `git diff --cached` exported the old 0011. The patches are
  now always exported from commits (`git diff HEAD~2 HEAD~1`).
- **Stack-clash test:** a first version had its 1 MiB `volatile` array
  optimized away (`memset` cast the qualifier off), so there was nothing
  to probe. Fixed in the test.

## Moved

VR512/VK16 under `HasKNC` and the MVEX flag bit moved to S2, where the
oracle can test them. In S1 nothing would have used them.
