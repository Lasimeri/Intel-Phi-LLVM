# 2026-10-16: S2, the Knights Corner MC layer

LLVM now assembles, encodes, prints and disassembles the Knights Corner
vector ISA (MVEX) and the KNC mask and scalar VEX forms under `-mcpu=knc`.
Everything was run on the rack and on card 0, with production idle.

## Patches

| Patch | Lines | What |
| --- | --- | --- |
| 0013 | 1,584 | `X86InstrKNC.td`: 330 defs generated from Intel's manual (`tools/knc-gen.c`), `isCodeGenOnly`, marked by class `KNCEnc`; `isMVEX` = TSFlags bit 55 (`X86II::MVEX`); `HasKNC`; `X86KNCInfo.{h,cpp,inc}`, the side table every MC piece reads; the code emitter's `MVEX` prefix kind (62h, P0 bit 3 and P1 bit 2 clear, E/SSS in place of z/L'L/b) and disp8*N from the memory conversion; the EVEX-compression and fold-table TableGen backends skip `KNCEnc` defs |
| 0014 | 588 | The assembler path for KNC mnemonics under `knc` (AT&T and Intel, decorations `{cdab}` `{1to16}` `{float16}` `{rn-sae}` `{eh}` `{%k1}`, the 26 compare pseudo-ops); `.allow_index_reg` accepted (a no-op: `%riz` and `%eiz` are always allowed); both instruction printers print KNC forms from the table |
| 0015 | 308 | The disassembler path: 62h with P1 bit 2 clear and the KNC VEX forms are decoded from the table when the subtarget has `knc`; everything else goes to the generic decoder |

## Where the instruction table comes from

`scripts/isa-extract.sh` runs `pdftotext -layout` on Intel's Xeon Phi
Coprocessor Instruction Set Architecture Reference Manual (327364-001,
SHA-256 pinned) and `isa/extract-isa.awk` on the text. The result,
`isa/knc-isa.txt` (804 records), holds 221 opcode rows, 334 conversion
tables (memory up- and down-conversions with their disp8*N, register
swizzles, static rounding), 28 pseudo-ops and their immediates.
`tools/knc-gen.c` turns it into the two generated files of patch 0013.
`make check` (`scripts/check-knc-gen.sh`) proves they are reproduced byte
for byte. The GPL binutils tables were never read into any of this; the
binutils build is only run, as the oracle.

## Where Intel's gas and the manual disagree

The gate is the oracle's bytes, so the oracle decides; each case is in
`isa/knc-overrides.txt` or in a comment beside the rule.

| Case | Manual (327364-001) | Oracle (MPSS 3.8.6 gas, `k1omni.s`) |
| --- | --- | --- |
| `vcvtfxpntdq2ps`, `vcvtfxpntudq2ps` | register form takes `{sae}` only | `{rn}` to `{rz-sae}`: MVEX.E=1, SSS=000 to 111 (lines 2756 to 2792) |
| `vpcmpnled` | pseudo-op of `vpcmpd` with `{nle}` | the real `vpcmpgtd` opcode (66.0F.W0 66) |
| `{sae}` with a swizzle on SAE-only forms | 1xx means SAE | MVEX.E=1, SSS = the swizzle (`{sae},%zmm3{dacb}` is SSS=011); `{sae}` alone is SSS=100 |
| `{eh}` on a register source | not described | MVEX.E=1 (`%zmm3{eh}`) |
| `vcvtdq2pd`, `vcvtps2pd`, `vcvtudq2pd` | `Si32(zmm2/mt)` | the register source is written `%ymm3` (the low half) |
| explicit `ds:` | | dropped where DS is the default segment |
| `vprefetch*`, `clevict*` | VEX and MVEX forms | MVEX only where disp8*64 is shorter than the VEX disp32 |

## Behavior to know

- **AVX forms under `-mcpu=knc`.** A mnemonic shared with AVX or AVX-512
  (`vmovaps`, `vaddps`, ...) means the Knights Corner instruction under
  `knc`; its xmm, ymm and EVEX forms are rejected ("invalid operands for
  Knights Corner instruction"). LLVM's x86 assembler otherwise ignores ISA
  features, and the S1 build accepted them, but on the card they would
  fault. Mnemonics KNC does not have are not affected.
- **NOP padding without `-mcpu`.** Patch 0003 (imported in S0) pads with
  one-byte NOPs whenever the subtarget lacks NOPL, and plain `llvm-mc`
  with no `-mcpu` has none. So this `llvm-mc` and Arch's differ there,
  as they did before S2. clang always passes a CPU.
- **Not yet:** `jkzd` and `jknzd`, the mask branches; they are in
  `k1omni-branch.s`, not in the gate. Codegen does not use any KNC
  instruction yet. That is S3.

## What went wrong on the way

- **First run:** 6,241 of 6,708. The rest were the gas cases above, plus a
  pseudo-op filter that ran before the rows that define `vpcmpeqd` and
  `vpcmpltd` had been read.
- **Harness:** awk numbers no file for an empty input, so with no errors
  the error file vanished and the encodings were read as errors. Files are
  told apart by `FILENAME` now.
- **Round trip:** SIB index 100 at scale 1 with a base that does not need a
  SIB (`-0x99(%rbx,%riz,1)`) was printed as `-0x99(%rbx)`, which assembles
  without the SIB byte. It is printed with `%riz` now.
- **Card, 515 of 516:** the probe adds the `{float16}` conversion to +0.0,
  and -0 + +0 is +0 under round to nearest. The card was right; the
  expectation was fixed.
- **Audit panic:** the stack's debug `phi-isa-audit` once panicked in
  iced-x86 1.21.0 (`decoder.rs:1421`, `data_ptr as u32` subtraction
  overflow). It depends on where the 108 MB `clang-23` is mapped, and a rerun
  passed. The release build wraps the same subtraction correctly.
- **`phi` and stdin:** `phi put`, `get` and `run` relay stdin, so inside a
  heredoc they swallow the rest of the script. Scripts here give them
  `</dev/null`.
